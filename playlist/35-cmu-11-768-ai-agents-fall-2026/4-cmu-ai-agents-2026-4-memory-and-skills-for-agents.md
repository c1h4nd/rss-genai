# CMU AI Agents 2026: 4. Memory and Skills for Agents

<https://www.youtube.com/watch?v=6zigF2a-2Pw>

- **Giriş ve motivasyon:** Önceki derste ele alınan context window içi belleğin ötesine geçilerek, görevler arasında dış depolarda (database, file system) bilgi saklama ve **skill induction** (deneyimden skill çıkarma) ile insan tarafından yazılan **skills** yaklaşımlarının bir araya gelme potansiyeli anlatılıyor [[00:25](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=25)]. Bir alışveriş sitesinde "Sony headphones" arayıp wish list'e eklemek ile ileride "wireless keyboard" fiyat aralığını bulmak gibi tekrarlayan alt görevlerin paylaşılabilir yapısının nasıl temsil edileceği tartışılıyor [[02:00](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=120)].
- **Agent güncelleme yöntemleri ve dış artifact avantajları:** Agent'ların güncellenmesi üç ana yola ayrılıyor: context window yönetimi (örneğin compaction), dış depolara yazma/okuma ve model ağırlıklarını güncelleme (SFT veya reinforcement learning) [[04:40](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=280)]. Milyon token'lık context window'larda bile çoklu görevlerde sınırların aşıldığı; dış artifact'ların ise farklı modeller arasında taşınabilirliği ve insanlar tarafından incelenip düzenlenebilirliği nedeniyle öne çıktığı vurgulanıyor [[05:21](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=321)].
- **Saklanabilecek deneyim türleri ve memory vs. skills:** Saklanabilecek deneyimler üç grupta inceleniyor: yüksek doğruluklu ama token maliyeti yüksek **episode** kayıtları, kullanıcı/ortam bilgilerini tutan **facts** (örneğin ChatGPT veya Anthropic bellek sistemleri) ve görev detaylarından soyutlanmış tekrarlanabilir **skills** [[09:22](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=562)]. Memory geçmiş etkileşimlerden saklanan bilgiyken, skill bir ortamda nasıl hareket edileceğine dair tekrar kullanılabilir bilgi (örneğin production'a çıkmadan önce kontrol listesi veya geçmiş başarılı aramalardan çıkarılan skill) olarak tanımlanıyor [[11:44](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=704)].
- **İnsan yazımı skills ve Agent Skills standardı:** Coding agent'larda linter, type hint, docstring ve pytest gibi tekrarlayan talimatları dosya olarak tutma fikri üzerinden **Agent Skills** standardı anlatılıyor [[14:01](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=841)]. Standart yapıda zorunlu **SKILL.md** dosyası (başında `name` ve `description` içeren YAML metadata ve ardından detaylı talimatlar) ile isteğe bağlı **scripts** (çalıştırılabilir kod), **references** (ek dokümantasyon) ve **assets** (şablonlar/kaynaklar) klasörleri bulunuyor [[15:31](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=931)].
- **Progressive disclosure ve sınırları:** Tüm skill'leri baştan context window'a doldurmamak için **progressive disclosure** kullanılıyor: 1. seviyede YAML metadata (`name` ve `description`) system prompt'ta yer alıyor (örneğin Hermes Agent'ta skill açıklamalarının yaklaşık 3,000 token civarında tutulması), 2. seviyede model `skill view` benzeri tool call ile `SKILL.md` içeriğini okuyor, 3. seviyede ise gerekirse `scripts`/`references`/`assets` dosyalarını yüklüyor [[17:33](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=1053)]. Fazla veya alakasız skill eklemenin modeli oyalayıp performansı düşürebileceği, trigger'ların modelin tool call seçimine bağlı olduğu ve **SkillsBench** değerlendirmesinde skill'lerin ortalama pass rate'i artırsa da az skill gerektiren görevlerde daha faydalı olduğu, bazı model/görevlerde ise performansı düşürebildiği aktarılıyor [[19:11](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=1151)]. Skill oluştururken sıfırdan soyut yazmak yerine geçmiş etkileşimlere dayanmanın ve pull request inceleme örneğindeki gibi insanın kabul ettiği yorumları model-based judge ve reasoning model ile analiz edip skill'i güncellemenin önemi vurgulanıyor [[29:36](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=1776)].
- **Bellek güncelleme, Reflection ve Trajectory retrieval:** **MemGPT** (2023) ile başlayan sistem yaklaşımında sistem talimatları, working context ve dış bellek arası okumalar/yazmalar tool call'larla yönetiliyor [[32:25](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=1945)]. **MeZero** (veya konuşmada geçen haliyle "me zero") ise yeni mesajlardan çıkarılan bilgileri embedding retrieval ile mevcut kayıtlarla karşılaştırıp yeni bilgi ekleme, güncelleme, çelişkili/geçersiz bilgiyi silme veya yok sayma imkânı sunuyor; bu yapı lineer attention'daki **Delta** yaklaşımının metin tabanlı karşılığı olarak ilişkilendiriliyor [[35:06](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=2106)]. Ayrıca **Reflection** ile deneme sonrası doğal dil geri bildirimi vererek bir sonraki denemeyi iyileştirme ve geçmiş **trajectory**'leri (ortam/kullanıcı mesajları, tool call'lar, chain of thought) havuzda tutup yeni görevde task açıklaması üzerinden retrieve ederek bağlama koyma yaklaşımı anlatılıyor [[38:54](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=2334)].
- **Skill induction: Text vs. Code (AWM, ASI, SkillWeaver, PolySkill):** Sabit element ID'lerine dayanan ham web aksiyonlarının sayfa veya site değişince kırıldığı belirtilerek **text** ve **code** temsilleri karşılaştırılıyor [[44:22](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=2662)]. **Agent Workflow Memory (AWM)** yaklaşımında başarılı trajectory'lerdeki tool call dizilerinden LLM aracılığıyla alt görev açıklamaları ve şablonlar çıkarılıp judge modeliyle doğrulandıktan sonra belleğe ekleniyor; harita görevlerinde baseline'ın yaklaşık %10 doğruluğuna karşın daha yüksek başarı ve daha karmaşık görevlere ulaşma sağlanıyor [[51:14](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=3074)]. **Code** tabanlı skill'lerde (örneğin Minecraft'ta fonksiyon bileşimi yapan **Voyager**, program induction odaklı **DreamCoder**, **ASI** ve **SkillWeaver**) fonksiyonlar tool olarak çağrılabiliyor, test edilebiliyor, linter geri bildirimiyle revize edilebiliyor ve sayfa/chain-of-thought adım sayısını azaltarak hız ve doğruluk kazandırıyor; ancak farklı sitelerde (örneğin Target'ta drop-down yerine radio button olması gibi) katı kalabiliyor [[46:31](https://www.youtube.com/watch?v=6zigF2a-2Pw&t=2791)]. Bu kırılganlığa karşı **PolySkill** yaklaşımında ortak arayüz/abstract class ve siteye özel somut implementasyonlar kullanılıyor [00:1:04:20].
- **Başarısızlıktan öğrenme, bellek budama ve RL ile skill induction:** **ReasoningBank** çalışmasında sadece başarı değil, başarısız trajectory'lerden (örneğin aramada `OR` mantığı yüzünden 5,000 sonuç gelip sayfalama hatası yaşanması) çıkarılan genel metin stratejilerinin (daha spesifik terim kullanmak veya daha fazla öğe görüntülemek gibi) performansı artırdığı, judge doğruluğundaki gürültünün belli bir eşiğe kadar tolere edilebildiği ve çok fazla/alakasız öğe getirmenin performansı düşürdüğü gösteriliyor [00:1:06:28]. Kullanım sıklığına göre cache benzeri budama yapmanın ve **reinforcement learning** ile ardışık görevlerde skill çıkarma, yeniden kullanım ve kütüphane boyutunu düzenleme ödüllerini doğrudan eğitmenin güncel araştırma yönleri olduğu belirtilerek ders sonlandırılıyor [00:1:11:56].
