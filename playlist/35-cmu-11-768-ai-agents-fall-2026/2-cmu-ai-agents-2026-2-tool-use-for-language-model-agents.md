# CMU AI Agents 2026: 2. Tool Use for Language Model Agents

<https://www.youtube.com/watch?v=jXChFB4JSyw>

- **Language Model Agent'ların Temel Farkı ve Tool Kavramı:** Tool, bir language model'ın kendi başına yalnızca token tahmin eden yapısının ötesine geçip harici bir bilgisayar programını çağırmasını sağlayan arayüzdür [[00:23](https://www.youtube.com/watch?v=jXChFB4JSyw&t=23)]. Iteratif tool call'lar yapan sistemler artık salt chat arayüzü değil birer agent olarak tanımlanır [[06:33](https://www.youtube.com/watch?v=jXChFB4JSyw&t=393)].
- **Tool Kullanımının İki Ana Faydası ve Kabiliyetleri:** Graham Neubig, birlikte yazdıkları survey çalışmasına atıfla tool'ların language model'ların yapamadığı şeyleri ekleyerek **extending** ve zaten yapabildikleri işleri daha hızlı/güvenilir hale getirerek **facilitating** sağladığını belirtir [[01:15](https://www.youtube.com/watch?v=jXChFB4JSyw&t=75)]. Başlıca kullanım alanları; güncel bilgiye erişim ile cevapları ground etme, hesaplayıcı veya Python ile kesin hesaplama yapma, kullanıcı gibi private state'lere erişme ve dış ortamda (browser veya API üzerinden) değişiklik yapmadır [[02:55](https://www.youtube.com/watch?v=jXChFB4JSyw&t=175)].
- **Yaygın Tool Kategorileri ve RAG Tartışması:** Ders kapsamında başlıca tool türleri; metinsel yanıtlar (döngüyü bir finish tool ile bitirmek veya tool çağırmamak yoluyla), web search, code execution, image generation ve özel fonksiyonlar (örneğin Instacart API ile alışveriş sepeti oluşturma) olarak ele alınır [[06:14](https://www.youtube.com/watch?v=jXChFB4JSyw&t=374)]. Image generation'da modelin kendi sorgusunu genişleterek API'ye gönderdiğine dikkat çekilir [[09:25](https://www.youtube.com/watch?v=jXChFB4JSyw&t=565)]. Ayrıca "RAG is dead" iddiasına karşı retrieval augmented generation'ın o kadar standart hale geldiği için artık fark edilmeden kullanıldığı savunulur [[07:42](https://www.youtube.com/watch?v=jXChFB4JSyw&t=462)].
- **Programmatic Tool Calling ve Güvenlik Riskleri:** Tek tek API çağırmak yerine kod yazarak (örneğin döngüler, değişkenler, kontrol akışı ve pandas gibi kütüphaneler kullanarak) tool çağırmak ifade gücünü artırır ve etkileşim tur sayısını düşürürken başarı oranını yükseltebilir (örneğin **Kodak** yaklaşımı) [[11:02](https://www.youtube.com/watch?v=jXChFB4JSyw&t=662)]. Ancak yüksek yetki nedeniyle infinite loop oluşması, ele geçirilmiş (compromised) kütüphanelerle güvenlik açıkları doğması, kısıtlamanın zorlaşması ve CPU/disk/memory etkileri gibi dezavantajlar bulunur; bu nedenle sandboxing önemlidir [[14:21](https://www.youtube.com/watch?v=jXChFB4JSyw&t=861)].
- **Tool Call Mekanizması, Model Formatları ve ID Eşleştirme:** Model çıktılarında metin devamı ve tool call token'ları birlikte yer alabilir (örneğin **ReAct** döngüsünün tek bir completion içine yerleşmesi veya reasoning modellerdeki thinking token'lar) [[16:26](https://www.youtube.com/watch?v=jXChFB4JSyw&t=986)]. Bu özel token'lar genellikle pre-training yerine **mid-training** ve reinforcement learning aşamalarında eklenir [[18:55](https://www.youtube.com/watch?v=jXChFB4JSyw&t=1135)]. Qwen, Mistral ve DeepSeek gibi modellerin tool call formatları farklılık gösterebilir; fine-tuning ve çağrılarda doğru chat template (örneğin Hugging Face `apply_chat_template`) kullanmak gerekir [[21:15](https://www.youtube.com/watch?v=jXChFB4JSyw&t=1275)]. Ayrıca paralel çağrılarda hangi sonucun hangi çağrıya ait olduğunu izlemek için her tool call'a ID atanır ve örneğin Anthropic'te eşleşmeyen bir tool call bırakmak geçersiz history hatasına yol açabilir [[25:18](https://www.youtube.com/watch?v=jXChFB4JSyw&t=1518)].
- **JSON Schema, Context-Free Grammar ve Constrained Decoding:** Model çıktılarının syntax, shape ve type kurallarına uyması için **JSON schema** kullanılır [[28:02](https://www.youtube.com/watch?v=jXChFB4JSyw&t=1682)]. JSON schema regular grammar ile ifade edilemez; ağaç yapısı ve stack gerektiren **context-free grammar** ve **pushdown automaton** ile doğrulanır [[30:49](https://www.youtube.com/watch?v=jXChFB4JSyw&t=1849)]. **XGrammar** gibi sistemler token üretimi sırasında geçersiz token'ların logit'lerini negatif sonsuza çekerek geçerli çıktı üretilmesini sağlar; ancak output token limitinin dolması durumunda yarım JSON üretimi gibi istisnalar yine de ortaya çıkabilir [[32:41](https://www.youtube.com/watch?v=jXChFB4JSyw&t=1961)].
- **REST API'ler ve Model Context Protocol (MCP):** FastAPI ile oluşturulan REST API'ler authentication (API key) sağlarken API yapısını JSON schema olarak sunar ve curl/bash üzerinden de çağrılabilir [[36:53](https://www.youtube.com/watch?v=jXChFB4JSyw&t=2213)]. Anthropic tarafından sunulan **MCP (Model Context Protocol)** ise keşif (list tools), transport (stdio, socket vb.) ve özellikle güvenlik açısından öne çıkar: agent'a doğrudan GitHub token gibi upstream credential vermek yerine MCP API key verilerek olası sızıntıların etkisi sınırlandırılabilir; ayrıca resmi MCP registry ve FastMCP gibi araçlar bulunur [[39:11](https://www.youtube.com/watch?v=jXChFB4JSyw&t=2351)].
- **Parallel Tool Calling ve Maliyet Paradoksu:** Bağımsız tool call'lar tek bir yanıtta birden fazla blok halinde üretilip Python'da örneğin `asyncio.gather` ile paralel çalıştırılabilir (bağımlı adımlar paralel yapılamaz) [[45:16](https://www.youtube.com/watch?v=jXChFB4JSyw&t=2716)]. Kısa süreli görev tamamlamaya yönelik reinforcement learning sayesinde son modeller paralel tool calling'de çok daha başarılıdır; bu da daha pahalı görünen güçlü modellerin doğru çözümü daha hızlı bulup paralel çağrı yapmasıyla görev bazında daha ekonomik olabildiği bir paradoks yaratır [[47:07](https://www.youtube.com/watch?v=jXChFB4JSyw&t=2827)].
- **Tool Use Değerlendirmesi ve Provider Farkları:** Tool kullanımını ölçmede **Berkeley Function Calling Leaderboard** (tek turlu, çok turlu, agentic tool calling, argüman hallucination, format sensitivity, verimlilik, reliability ve safety boyutlarıyla) önemli bir kıstastır [[49:24](https://www.youtube.com/watch?v=jXChFB4JSyw&t=2964)]. **OpenRouter** tool call error rate verilerinde aynı modelin farklı provider'lar üzerinden sunulmasında hata oranının %15 ile %0,01-%0,05 arasında değişebildiği gösterilir; bunun nedenleri arasında quantization seviyesi (örneğin FP8'e kıyasla daha agresif sıkıştırma yapan FP4), speculative decoding, farklı constrained decoding uygulamaları (örneğin vLLM veya SGLang kullanımı ya da eksikliği) ve provider güvenilirliği yer alır [[51:39](https://www.youtube.com/watch?v=jXChFB4JSyw&t=3099)].
- **Kapanış ve Ders Duyuruları:** Ders; tool use'un katmanlı bir yapı olduğu, syntax/grammar kısıtlarının semantic doğruluğu (örneğin yazılan Python kodunun mantıksal olarak hatasız olmasını) garanti etmediği ve bu konuların ilk ödevde (harness/agent kurulumu) kullanılacağı vurgulanarak tamamlanır; bir sonraki dersin long context language model'larda context management olacağı ve Canvas'taki ilk yansıtma ödevinin teslim edilmesi gerektiği hatırlatılır [[55:49](https://www.youtube.com/watch?v=jXChFB4JSyw&t=3349)].
